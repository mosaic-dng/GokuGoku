# GokuGoku v1.3.0 发布设计

## 目标

将当前 `agent/code-review-optimizations` 分支中的渲染边界加固和可选延后提醒功能作为正式 `v1.3.0` 发布。同步更新仓库 README、真实应用截图和 Windows x64 便携版，确保下载内容与文档展示一致。

## README 与截图

- 保留现有首次设置、主界面和设置截图。
- 用当前源码生成的普通提醒截图替换 `docs/screenshots/reminder.png`。
- 新增 `docs/screenshots/reminder-snooze-menu.png`，展示 5、15、30 分钟菜单。
- README 的催水提醒区域并排展示普通状态与展开菜单状态。
- 功能说明明确延后提醒支持 5、15、30 分钟。
- 下载文件名和验收版本更新为 `GokuGoku-v1.3.0-Windows-x64.zip` 与 `v1.3.0`。
- 测试与截图数量更新为本次验证结果；便携目录和 ZIP 大小使用本地实际构建值。

## 版本与 Windows 验收

- 将 `package.json` 和 `package-lock.json` 的应用版本同步更新为 `1.3.0`。
- 不改变 schema v3、用户数据路径或迁移逻辑。
- 从当前源码重新构建 Windows x64 便携目录。
- 验证运行文件、语言包、ASAR 排除项、EXE 产品版本和包体大小。
- 使用打包后的 `GokuGoku.exe` 在隔离数据目录运行完整 Electron shot mode，并验证全部截图尺寸与交互断言。

## 发布流程

1. 在当前功能分支完成文档、截图和版本更新并通过全部验证。
2. 提交 release prep，并确认工作树干净、当前分支可从 `main` 快进。
3. 将本地 `main` 快进到 release prep 提交并推送 `origin/main`。
4. 在该提交创建注释标签 `v1.3.0`，随后单独推送标签。
5. 等待 Release 工作流完成，核对 `GokuGoku-v1.3.0-Windows-x64.zip`、README 文案和线上截图。

不创建 PR，不强推，不移动或复用已有标签。若本地验证失败，不更新 `main`。若标签触发后的远程工作流失败，保留失败记录并通过后续补丁版本修复。

## 验收标准

- README 在线展示普通提醒与三档延后菜单截图。
- `package.json`、`package-lock.json`、EXE 产品版本和 Git 标签均为 `1.3.0`。
- Node 全量测试、Windows 包验证和打包后 Electron shot mode 全部通过。
- GitHub Release 成功发布且只包含完整 Windows x64 便携 ZIP。
- `main`、`v1.3.0` 和 Release 指向同一已验证提交。
